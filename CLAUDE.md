# Документация Cognopolis для людей — правила репо

Это **витрина проекта для людей**: команды, студентов курса, гостей. Красивая, объясняющая,
разложенная по папкам. Прежде чем писать сюда — прочитай этот файл; рабочий скилл —
`cognopolis-docs-human` (в репо движка, `.claude/skills/`).

## Место в двухрепной документации

| Репо | Аудитория | Роль |
|---|---|---|
| `Train_of_Thought-Cognopolis-obsidian` (vault) | агенты + автор-куратор | **память проекта, единственная истина**: текущее устройство систем, статус (`State.md`), решения, журнал |
| **этот репо** (`-for-man`) | люди | **презентационный слой**: объясняет игру и проект человеку; истину не хранит, а пересказывает |

Противоречие этой витрины vault'у или коду = **баг витрины** — чинится здесь, не в vault.

## Структура

```
README.md            — обложка РЕПО для GitHub (в вики не публикуется)
docs/index.md        — главная страница вики: обложка с плитками и скриншотом
docs/01-обзор/       — концепция, роадмап (человеческим языком)
docs/02-игроку/      — быстрый старт, тур по экранам, свой агент
docs/03-системы/     — игровые системы: мир, бой, крафт, экономика, жители, Подземье
docs/04-разработчику/ — ВНУТРЕННЕЕ: в публичную вики не публикуется (build.sh вырезает)
docs/assets/img/     — скриншоты игры с обводками-выносками
docs/assets/css/     — тема вики поверх MkDocs Material
tools/screenshots/   — харнесс съёмки кадров (см. его README)
```

Главная вики и обложка репо — **разные файлы**: `docs/index.md` пишется под разметку Material
(плитки, кнопки, скриншот), `README.md` — простым markdown, чтобы читался на GitHub без рендера.
Если `docs/index.md` удалить, `build.sh` вернётся к старому поведению и застейджит README главной.

## Железные правила

1. **Никаких статусов и дат в тексте.** Ни «✅ готово», ни «задеплоено 2026-…», ни счётчиков
   тестов. Единственная допустимая формула: «актуальное состояние — vault `State.md`».
2. **Каждая страница заканчивается блоком «Источники»** — список vault-страниц (и файлов кода),
   из которых она сделана. По нему скилл находит, что перегенерировать при изменениях.
3. **Тон — живой русский для новичка**: термин объясняется при первом употреблении; D-номера
   решений в тексте не нужны (глубина — по «Источникам»); таблицы и mermaid-схемы приветствуются.
   Обращение — на «вы». Абзац — максимум три строки; дальше список, таблица или скриншот.
   Литературные обороты («сердце игры», «эпохи игрока», «кульминация курса») запрещены:
   витрина объясняет, а не украшает.
4. **Никаких секретов**: ни паролей, ни ключей, ни приватных IP/DSN — даже в примерах.
5. **Не дублировать справочники**: каталоги рецептов/зданий/цен/статов живут в игре (`/codex` и
   `GET /recipes|/buildings|/items|/stats`) — ссылайся, не копируй значения.
6. **Процесс описывается как инструкция**, а не как рассказ: пронумерованные шаги, каждый
   начинается с глагола, подписи кнопок и вкладок цитируются **дословно как в интерфейсе**
   («добавить в очередь», вкладка «аккаунт»), маршрут экрана — кодом (`#/town-hall`).
7. **У процесса должен быть скриншот с обводками.** Кадры — только из `docs/assets/img/`
   (снимаются `tools/screenshots/shoot.py`), под каждым — нумерованная легенда, номера совпадают
   с номерами на картинке. Поменялся интерфейс — кадр переснимается, иначе он врёт.

## Разметка страницы (компоненты темы)

Тема лежит в `docs/assets/css/wiki.css`. Готовые куски — использовать их, а не изобретать:

| Что нужно | Как пишется |
|---|---|
| сводка «если коротко» в начале | `<div class="cg-tldr" markdown>` + 3–5 буллетов |
| шаги процедуры | `<div class="steps" markdown>` + нумерованный список |
| скриншот | `<figure class="shot" markdown>` + `![alt](…)` + `<figcaption>` |
| легенда к обводкам | `<div class="callouts" markdown>` + нумерованный список |
| плитки разделов | `<div class="grid cards" markdown>` (только на главной) |
| «Источники» | раскрывашка `??? info "Источники — из чего сделана страница"` |

Скриншоты открываются во весь экран кликом (плагин glightbox) — мелкие подписи интерфейса
читаются только так, поэтому кадр всегда полноразмерный, а не обрезанный «для красоты».

## Обновление

Витрина обновляется **событийно**: изменилась система → постфлайт `cognopolis-design-canon`
(в репо движка) содержит пункт «человеческая витрина» → скиллом `cognopolis-docs-human` найди
затронутые страницы по блокам «Источники» и перепиши их по обновлённому vault. Пуш — обычный
git push (CI/деплоя у этого репо нет).

## Рендер в HTML (публикация как вики)

`./build.sh` — одна команда, собирает статическую вики (MkDocs Material) в `site/`:
главная берётся из `docs/index.md`, `docs/` рендерится как есть; `.build/` и `site/`
генерируются и в git не идут. Публикация на `kindomklaster.com/wiki` — маршрут Caddy в репо
движка (заготовка — `deploy/caddy-wiki-route.patch`), выкладка `site/` на прод — руками
автора/продюсера, деплой-контура у этого репо нет.
